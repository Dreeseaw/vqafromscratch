## Modeling Read

This experiment rules out the “hard frozen-LM routing barrier” story as the main explanation for K=8 fragility.

What it supports instead:
- the original K=8 bottleneck exported semantically useful tokens in the wrong LM-facing geometry
- the remap diagnostic found that geometry externally
- bottleneck-only training with `L_format` can internalize most of that correction
- once internalized, the external remap becomes stale and destructive

The remaining gap to full `keep-3` K=8 is now small and localized:
- `overall`: `0.5900` vs `0.6154`
- `yes/no`: `0.7393` vs `0.7611`
- `number`: `0.4499` vs `0.4583`
- `other`: `0.5134` vs `0.5462`

So the open problem is no longer “can a frozen LM consume 8 tokens at all?”
It can.

The open problem is:
- how to recover the last `other` / descriptive-compositional gap
- without reintroducing the old adapter machinery wholesale

## Recommendation

Next experiment should not be “put the old remap back.” That answer is now clearly no.

Best next move:
- keep the no-adapter, no-remap format-aligned bottleneck path
- extend bottleneck-only training modestly or tune the `L_format` anneal shape
- if extra capacity is needed, prefer a very small jointly trained downstream aid rather than restoring the old Cement adapter stack unchanged

Short version:
- format alignment worked
- the remap was mostly a teacher, not a permanent component
- the bottleneck now carries LM-usable geometry directly
